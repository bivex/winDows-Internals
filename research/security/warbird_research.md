# Исследование инфраструктуры Warbird в ядре Windows 11

## Введение

**Warbird** — это одна из самых скрытных и сложных систем защиты внутри Windows. Разработанная командой Microsoft DRM (Digital Rights Management), она представляет собой среду исполнения защищенного кода, которая используется для обфускации, лицензирования и предотвращения реверс-инжиниринга критических компонентов ОС.

В отличие от стандартных механизмов защиты, Warbird глубоко интегрирован непосредственно в исполнительную часть ядра (`ntkrnlmp.exe`).

## Основные функции и механизмы

Исследование символов и кода ядра Windows 11 (ARM64) выявило следующие направления работы Warbird:

### 1. Управление контекстом (Process/Thread Tracking)

Warbird отслеживает выполнение внутри специфических процессов и потоков. 
*   `nt!WbGetWarbirdProcess`
*   `nt!WbGetWarbirdThread`

Ядро хранит списки защищенных процессов. Одной из точек входа для поиска этих списков является `nt!MiSystemPartition` (смещение `+0x6340` на исследуемой ARM64 системе).

### 2. Динамическая расшифровка (Encryption Segments)

Warbird позволяет хранить код в зашифрованном виде и расшифровывать его "на лету" только тогда, когда он необходим для исполнения.
*   `nt!WbDecryptWarbirdEncryptionSegmentBlockV0/V1`: функции, отвечающие за расшифровку блоков кода.
*   `nt!WbInitializeEncryptionSegment`: инициализация защищенных сегментов при загрузке модуля.

Это делает статический анализ файлов (таких как `ClipSp.sys` или `sppsvc.exe`) практически невозможным без предварительной расшифровки.

### 3. Защита кучи и выполнения (Heap Execution)

Современные версии Warbird включают механизмы проверки целостности аргументов вызовов, происходящих из динамической памяти.
*   `nt!WbValidateHeapExecuteCallArguments`
*   `nt!WbUpdateHeapExecutedCallArgumentList`
*   `nt!WbCreateHeapExecutedBlock`

Эти функции предотвращают попытки подмены кода в памяти (Monkey Patching) или внедрение вредоносного кода в защищенную область кучи.

### 4. Стелс-технологии и Anti-Tamper

Warbird обладает функциями, которые позволяют ему обходить стандартные механизмы защиты памяти самого ядра для внесения изменений в защищенный код.
*   `nt!WbMakeUserExecutablePagesKernelWritable`: позволяет ядру временно делать исполняемые страницы пользователя доступными для записи, что используется для расшифровки или патчинга защищенного кода без уведомления стандартных подсистем аудита.

## Области применения

Warbird защищает компоненты, связанные с:
1.  **Лицензированием**: Software Protection Platform (`sppsvc.exe`), проверка ключей активации.
2.  **DRM**: Защита мультимедийного контента (PlayReady).
3.  **Kernel Integrity**: `ClipSp.sys` (Component Licensing Store), который проверяет подлинность системных файлов и приложений из Store.

## Особенности на ARM64

На архитектуре ARM64 Warbird активно использует специфические инструкции для обеспечения целостности потока управления:
*   `pacibsp` / `autibsp`: Pointer Authentication Code для защиты адреса возврата в стеке.
*   `ldapr` / `stlr`: инструкции с семантикой Acquire/Release для атомарного доступа к состоянию Warbird.

## WinDbg команды для исследования

```text
# Найти все функции Warbird в ядре
x nt!Wb*

# Проверить наличие защищенных процессов (требует анализа MiSystemPartition)
dq nt!MiSystemPartition+6340 L10

# Дизассемблировать диспетчер операций Warbird
u nt!WbDispatchOperation$filt$0
```

## Заключение

Инфраструктура Warbird — это "ядро внутри ядра". Она предоставляет мощные инструменты для защиты интеллектуальной собственности Microsoft и обеспечения безопасности ОС. Для исследователя безопасности Warbird представляет интерес как пример реализации высокоуровневой обфускации и виртуализации кода на уровне режима ядра.
