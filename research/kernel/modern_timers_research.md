# Исследование современной инфраструктуры таймеров в Windows 11 (ARM64)

## Введение

Таймеры являются критическим компонентом для снижения задержек (**latency**) и управления энергопотреблением. В Windows 11 инфраструктура таймеров претерпела значительные изменения, перейдя к модели **Tickless Kernel** и глубокой интеграции с политиками питания (PPM).

## Основные компоненты системы таймеров

### 1. Механизм Tickless (Dynamic Tick)

Традиционно Windows использовала фиксированный интервал прерываний таймера (обычно 15.6 мс). В современных сборках (напр. 26100 ARM64) ядро перешло на динамические тики:
*   Функция `nt!KeGetNextClockTickDuration` позволяет ядру вычислять время следующего прерывания на основе ближайшего активного таймера.
*   Это позволяет процессору дольше оставаться в глубоких состояниях сна (C-states), не просыпаясь по бесполезным прерываниям "пустого" тика.

### 2. Интеграция с Processor Power Management (PPM)

Обнаружена глубокая связь между планированием таймеров и таблицей политик `nt!PpmPolicyConfigTable`. 
Ядро проверяет флаги PPM в следующих операциях:
*   `nt!KeSetTimer2` — установка нового таймера.
*   `nt!ExpUpdateTimerResolution` — изменение системного разрешения.
*   `nt!KeGetClockTimerResolution` — получение текущей точности.

Это означает, что **фактическая точность таймера может быть ниже запрошенной**, если активна политика энергосбережения или поток находится в фоновом режиме (низкий QoS).

### 3. Современные примитивы: Timer2 и IRTimer

Windows 11 активно использует новые системные вызовы для работы с временем:
*   `nt!NtCreateTimer2` / `nt!NtSetTimer2`: замена старым `NtCreateTimer`. Поддерживают расширенные флаги для высокой точности и управления коалесценцией (объединением).
*   `nt!NtSetIRTimer`: (Interrupt Response Timer) используется для сверхточных прерываний, критичных для мультимедиа и реального времени.

### 4. Коалесценция таймеров (Timer Coalescing)

Для экономии энергии ядро "группирует" таймеры разных процессов так, чтобы они срабатывали одновременно.
*   Инфраструктура управляется через `nt!PopCoalescing*` (Power Policy Coalescing).
*   К механизму подключен даже Cache Manager (`nt!CcCoalescingCallBack`), что позволяет сбрасывать файловый кэш синхронно с пробуждением процессора по таймеру.

## Практические выводы для оптимизации

1.  **Высокое разрешение (0.5ms)**: Вызов `timeBeginPeriod(1)` или `NtSetTimerResolution(5000, ...)` все еще работает, но его эффект может быть нивелирован политикой `KeDisableLowQosTimerResolution`, если ваше приложение помечено как фоновое (Background QoS).
2.  **Waitable Timer High Resolution**: Использование флага `CREATE_WAITABLE_TIMER_HIGH_RESOLUTION` в пользовательском режиме задействует в ядре путь через `KeSetTimer2` с обходом стандартной коалесценции, что дает минимальный джиттер.
3.  **ARM64 Latency**: На ARM64 точность обеспечивается системным счетчиком частоты (Generic Timer), доступ к которому из ядра осуществляется через сверхбыструю инструкцию `ldapr` (Load-Acquire PC-Relative), что видно в `nt!KeQueryInterruptTimePrecise`.

## Полезные WinDbg команды

```text
# Проверить активное разрешение таймера (в 100-нс единицах)
dd nt!PsDfssActiveTimerResolution100ns L1

# Список всех запросов на изменение разрешения
dl nt!ExpTimerResolutionListHead

# Посмотреть статистику срабатываний таймеров на текущем ядре
dt nt!_KPRCB @$pcr TimerTable
```
