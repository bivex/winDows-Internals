# Исследование паттерна Kernel PMDB Communication и методов скрытия потоков

## Введение

Паттерн **PMDB (Process Memory Data Bridge)** — это метод скрытого взаимодействия между User-mode приложением и Kernel-mode драйвером. Основная идея заключается в отказе от стандартных механизмов (IOCTL, системные вызовы) в пользу прямой синхронизации буферов памяти и использования скрытых системных потоков.

## Механизм скрытия системного потока

Для минимизации обнаружения античитами (EAC, BE) или инструментами мониторинга, драйвер манипулирует внутренними структурами ядра для текущего потока.

### 1. Флаг KTHREAD::SystemThread

Флаг `SystemThread` указывает планировщику и функциям аудита, что поток был создан ядром.

*   **Локация (ARM64)**: `nt!_KTHREAD + 0x6c` (MiscFlags), бит 10.
*   **Логика проверки**: Функция `nt!PsIsSystemThread` извлекает этот бит:
    ```asm
    ldr  w8, [x0, #0x6C]  ; Загрузка MiscFlags
    ubfx w0, w8, #0xA, #1 ; Извлечение 10-го бита
    ret
    ```
*   **Скрытие**: Обнуление этого бита заставляет систему считать, что поток принадлежит пользовательскому процессу, что помогает обходить простые проверки на "несанкционированные системные потоки".

### 2. ETHREAD::KernelStackReference

Это поле используется ядром для отслеживания ссылок на стек ядра.

*   **Локация (ARM64)**: `nt!_ETHREAD + 0x5cc`.
*   **Скрытие**: Обнуление этого поля затрудняет трассировку стека (Stack Walking) внешними инструментами, так как удаляет явную связь потока с его стеком в определенных контекстах аудита.

## Механизм связи (PMDB)

Вместо регистрации устройства через `IoCreateDevice`, драйвер использует периодическую синхронизацию.

### 1. Использование MmCopyVirtualMemory

Основным инструментом является функция `nt!MmCopyVirtualMemory`. Она позволяет безопасно копировать данные между адресными пространствами разных процессов, минуя необходимость использования `KeStackAttachProcess` (которая может быть перехвачена).

```cpp
NTSTATUS MmCopyVirtualMemory(
    IN PEPROCESS SourceProcess,
    IN PVOID SourceAddress,
    IN PEPROCESS TargetProcess,
    IN PVOID TargetAddress,
    IN SIZE_T BufferSize,
    IN KPROCESSOR_MODE PreviousMode,
    OUT PSIZE_T ReturnSize
);
```

### 2. Алгоритм работы
1.  **Инициализация**: User-mode приложение выделяет буфер команд (Command Buffer) и передает его адрес драйверу (например, через общую память или один стартовый IOCTL).
2.  **Polling (Опрос)**: Скрытый системный поток в драйвере с определенным интервалом вызывает `MmCopyVirtualMemory`, чтобы прочитать буфер из памяти процесса.
3.  **Исполнение**: Если в буфере найден флаг новой команды, драйвер выполняет её (например, чтение памяти другого процесса).
4.  **Ответ**: Результат записывается обратно в буфер в памяти процесса через ту же `MmCopyVirtualMemory`.

## Преимущества и недостатки

### Преимущества:
*   **Отсутствие Device Object**: Нет необходимости создавать устройство, которое можно найти через `IoGetDeviceObjectPointer`.
*   **Обход перехватов**: `MmCopyVirtualMemory` — это низкоуровневая функция MM, которую реже мониторят, чем `NtDeviceIoControlFile`.
*   **Стелс-потоки**: При правильной очистке структур поток выглядит как легитимный поток процесса, в котором он "паразитирует".

### Недостатки:
*   **CPU Overhead**: Постоянный опрос (polling) буфера потребляет ресурсы CPU.
*   **Обнаружение по паттернам**: Современные античиты проверяют `MiscFlags` и целостность `ETHREAD`, а также ищут потоки, чей стартовый адрес находится вне модулей процесса.
*   **Риск BSOD**: Прямая манипуляция недокументированными полями структур ядра (`0x6c`, `0x5cc`) крайне зависима от версии Windows и может привести к нестабильности.

## WinDbg команды для исследования

```text
# Проверить флаг SystemThread для текущего потока
dt nt!_KTHREAD @$thread MiscFlags

# Проверить KernelStackReference
dt nt!_ETHREAD @$thread KernelStackReference

# Найти адрес MmCopyVirtualMemory
x nt!MmCopyVirtualMemory
```
