# Исследование Scheduler QoS и приоритетов в Windows 11 (ARM64)

## Введение

Windows 11 представила развитую систему **Quality of Service (QoS)** для управления потоками, особенно на гибридных архитектурах (P/E-ядра) и ARM64. Основная цель — ограничение ресурсов для фоновых задач (**Throttling**) и приоритизация интерактивных приложений.

## Архитектура QoS в ядре

Исследование структуры `nt!_KTHREAD` и `nt!_ETHREAD` выявило ключевые поля, отвечающие за планирование:

### 1. Поля QoS в структурах потока

| Структура | Смещение | Поле | Описание |
|-----------|----------|------|----------|
| `_KTHREAD` | `+0x1fc` | `BamQosLevel` | Уровень QoS от Background Activity Moderator. |
| `_KTHREAD` | `+0x1fd` | `HardwareFeedbackClass` | Класс обратной связи от железа (используется для выбора P/E ядер). |
| `_KTHREAD` | `+0x33b` | `WobPriority` | Приоритет "Work On Behalf" (выполнение от имени другого потока). |
| `_KTHREAD` | `+0x3de` | `PpmPolicy` | Политика Processor Power Management для конкретного потока. |
| `_ETHREAD` | `+0x630` | `WorkOnBehalfThread` | Указатель на поток, от имени которого идет работа (наследует его QoS). |

### 2. Уровни BamQosLevel

В ходе живого анализа были зафиксированы следующие значения:
*   **01 (High Performance)**: Активные окна, такие как `explorer.exe`.
*   **02 (Balanced/Medium)**: Фоновые процессы с умеренным приоритетом (напр. `SearchHost.exe`).
*   **06 (Utility/Idle)**: Системные простои (Idle threads).

## Алгоритмы принятия решений

### Функция `nt!KiComputeThreadQos`

Эта функция является центральным узлом для определения текущего QoS потока. Она анализирует:
1.  **Thread Flags**: Проверяет, не является ли поток системным или критическим.
2.  **Work On Behalf (WOB)**: Если поток работает "от имени" другого (через `+0x630`), он заимствует `BamQosLevel` целевого потока.
3.  **Process QoS**: Учитывает настройки родительского процесса из `nt!_KPROCESS + 0x90`.
4.  **User Presence**: В Windows 11 учитывается "присутствие пользователя" (через `Feature_UserPresenceThrottling`). Если пользователь отошел, QoS для многих потоков принудительно понижается.

### Таблица отображения `nt!KiThreadPolicyToQosMappingTable`

Ядро использует внутреннюю таблицу для маппинга Win32-политик в уровни QoS. Обнаруженные значения: `07, 02, 01, 00, 05, 00, 07, 02`.
Значение `05` соответствует режиму **Eco Mode**, который можно увидеть в Диспетчере задач.

## Влияние на оптимизацию

1.  **Предотвращение Throttling**: Чтобы поток не был "задушен", он должен иметь `BamQosLevel = 1`. Это достигается либо через фокус окна, либо через вызов `SetThreadInformation` с классом `ThreadPowerThrottling`.
2.  **Эффективность WOB**: Использование механизмов "выполнения от имени" позволяет фоновым сервисам временно получать приоритет пользовательского процесса, что критично для отзывчивости RPC/ALPC вызовов.
3.  **Hardware Feedback**: На ARM64 (Apple Silicon/Snapdragon) ядро использует `HardwareFeedbackClass` для динамического переключения потока между ядрами разной мощности в зависимости от его текущей нагрузки и лимитов QoS.

## WinDbg команды для анализа

```text
# Посмотреть QoS текущего потока
dt nt!_KTHREAD @$thread BamQosLevel HardwareFeedbackClass

# Найти все функции вычисления QoS
x nt!KiCompute*Qos*

# Проверить наличие Throttling для процесса
!process <address> 1
```
