# Исследование методов захвата экрана и детекции пикселей (Kernel-Level)

## Введение

Задача высокопроизводительной детекции пикселей (например, для систем компьютерного зрения или авто-аима) упирается в архитектуру графической подсистемы Windows (WDDM и Dxgkrnl). Традиционные методы пользовательского режима работают медленно из-за высоких накладных расходов на контекстные переключения и синхронизацию с Desktop Window Manager (DWM).

В этом исследовании мы рассмотрим, как различные методы выглядят со стороны ядра и почему DXGI Desktop Duplication является оптимальным программным выбором.

## 1. GDI: `GetPixel` и `BitBlt`

Исторически старые методы, работающие через подсистему `win32k.sys`.

*   **Как это выглядит в ядре:** Вызов `BitBlt` транслируется в системные вызовы `NtGdiBitBlt`, которые блокируют поверхности GDI. Для захвата экрана ядру необходимо запросить у драйвера видеокарты (через `DxgkCb*` коллбэки) чтение из VRAM в системную память.
*   **Узкое место:** Процесс включает чтение из Uncached/Write-Combined памяти PCIe-устройства (GPU) в оперативную память процессора. Это вызывает блокировки шины PCIe. Кроме того, GDI не имеет прямого доступа к эксклюзивным полноэкранным DirectX приложениям (Exclusive Fullscreen), так как они обходят DWM.
*   **Вердикт:** Медленно (20-40 мс на кадр), высокая нагрузка на CPU.

## 2. DXGI Desktop Duplication API (DDA)

Это современный стандарт, появившийся в Windows 8. DDA работает в обход GDI и взаимодействует напрямую с DirectX Graphics Kernel (`dxgkrnl.sys`).

### Как это устроено в ядре (Анализ `dxgkrnl.sys`)

При инициализации захвата через DXGI создается объект `OUTPUTDUPL_MGR` внутри ядра.

1.  **Авторизация:** Ядро проверяет права процесса через `dxgkrnl!OUTPUTDUPL_MGR::CurrentProcessHasCapturePermission`.
2.  **Синхронизация с DWM:** Когда Desktop Window Manager (или полноэкранная игра) завершает отрисовку кадра и вызывает `Present`, управление переходит в ядро.
3.  **Перехват кадров:** Внутри `dxgkrnl` срабатывает `dxgkrnl!OUTPUTDUPL_MGR::ProcessPresent`. Эта функция уведомляет диспетчер дубликации о появлении нового кадра.
4.  **Dirty Rectangles:** Ядро вычисляет "грязные" (измененные) регионы экрана. Вызов `dxgkrnl!OUTPUTDUPL_MGR::GetFrameInfo` возвращает эти метаданные в пользовательский режим.

### Преимущества DDA:
*   **Zero-Copy в RAM:** DDA возвращает текстуру (`ID3D11Texture2D`), которая физически **остается в видеопамяти (VRAM)**. Процессор (CPU) вообще не участвует в копировании кадра.
*   **Асинхронность:** DDA блокирует ваш поток до тех пор, пока `dxgkrnl` не сигнализирует о новом кадре (соответствует частоте обновления монитора — 144Hz/240Hz). Задержка (latency) составляет < 1-2 мс.

## 3. Обработка пикселей (Compute Shaders)

Получив текстуру экрана в VRAM через DDA, *худшее*, что можно сделать — это вызвать метод `Map` (через `ID3D11DeviceContext::Map`), чтобы скопировать текстуру из видеокарты в оперативную память для поиска нужного пикселя с помощью `for (int x...)`. Это убьет всю производительность из-за пропускной способности шины PCIe.

**Правильный (High-Performance) путь:**
1.  Передать полученную от DDA `ID3D11Texture2D` как входной ресурс (Shader Resource View) в **Compute Shader** (вычислительный шейдер DirectX/Vulkan).
2.  Запустить шейдер. Тысячи ядер GPU параллельно просканируют текстуру за микросекунды.
3.  Шейдер записывает координаты найденного пикселя (X, Y) в крошечный выходной буфер (Unordered Access View) размером в несколько байт.
4.  С помощью CPU вы читаете только этот крошечный буфер.

## 4. Hardware PCIe DMA (Аппаратный подход)

Если программные методы подвергаются детектированию античитами (например, Vanguard или EAC могут блокировать создание `OUTPUTDUPL_MGR` или внедрять хуки на DXGI функции), используется аппаратный подход.

*   В PCIe слот устанавливается устройство (например, на базе ПЛИС/FPGA — Screamer PCIe).
*   Устройство напрямую читает физическую память через шину PCIe (Direct Memory Access), минуя CPU и операционную систему.
*   Координаты фреймбуферов извлекаются из структур `dxgkrnl`, и пиксели считываются "снаружи".
*   Анализ производится на другом, физически отключенном от интернета компьютере.

## Заключение

Для программного поиска пикселей на экране в современных версиях Windows **строго рекомендуется использовать связку DXGI Desktop Duplication API + Compute Shaders**. Этот метод работает синхронно с планировщиком Dxgkrnl (`ProcessPresent`), обеспечивает нулевую нагрузку на центральный процессор и латентность на уровне 1 мс. Традиционные методы (GDI) не соответствуют требованиям высоконагруженных систем.
