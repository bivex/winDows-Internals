# Hyper-V (`HVL`) Kernel Architecture & Empirical Research (ARM64)

**Environment:**
- **OS:** Windows 11 Pro ARM64 (Build 26100.1)
- **Architecture:** ARM64 / AArch64 (EL1 Root Partition Kernel)
- **Debugger:** WinDbg Kernel Debugger via MCP Agent (`http://10.211.55.5:44445/mcp`)
- **Tooling:** `structscan v4.0` (Bayesian Multi-Feature Field Classifier & C/C++ Header Synthesizer)

---

## 1. Executive Summary

Гипервизор Microsoft Hyper-V является микроядерным гипервизором 1-го типа (Type-1 Bare-Metal Hypervisor), работающим на уровне привилегий **EL2** (на ARM64) или **VMX Root** (на x64). Операционная система Windows исполняется в **Root Partition** (EL1), взаимодействуя с гипервизором через **Hypervisor Interface Layer (HVL)** в ядре (`ntoskrnl.exe`).

Поскольку Microsoft практически не публикует PDB-символы для внутренних структур Hyper-V (`HV_PARTITION`, `HV_VP`, `HV_MESSAGE`, `HV_CONNECTION`), настоящее исследование направлено на эмпирическое восстановление их топологии и мета-провайдеров в оперативной памяти с помощью `structscan v4.0`.

## 2. Архитектура Мета-Провайдеров Hyper-V (`nt!HypervisorMetaProviderContext`)

## 5. Механика Гиперколлов (Hypercalls) на ARM64 vs x64

Взаимодействие ядра Windows (EL1) с микроядром Hyper-V (EL2) осуществляется через специальные инструкции выполнения гиперколла:

* **ARM64 (AArch64):** Используется инструкция `HVC #0` (Hypervisor Call) через обертку `nt!HvlpInvokeGetPageListHypercall`.
* **x64 (AMD64 / Intel VT-x):** Используется инструкция `VMCALL` (Intel) или `VMMCALL` (AMD).

### Главные гиперколлы ядра:
1. `HvCallPostMessage` — Отправка межпартиционного сообщения (`HV_MESSAGE`).
2. `HvCallSignalEvent` — Сигнал события между guest/root партициями.
3. `HvCallCreateVirtualProcessor` — Динамическое создание vCPU.
4. `HvCallModifyVtlProtectionMask` — Управление защитой VTL (Virtual Trust Level 0 / VTL 1 - Credential Guard).

## 6. Защита VBS (Virtualization-Based Security) и Память Партиций

Объект системной партиции `nt!MiSystemPartition` (`0xfffff802ac64c000`) управляет изоляцией страниц памяти через Second Level Address Translation (SLAT / EPT). 

### Безопасность и Forensics:
* **Изоляция Credential Guard (VTL 1):** Процесс `lsass.exe` защищен изоляцией VTL 1. Прямой доступ из ядра EL1 (VTL 0) вызывает немедленный `SLAT Violation Violation Fault` на уровне гипервизора EL2.
* **Обнаружение уязвимостей (Hyper-V Escape):** Анализ структуры `AlpcMetaProviderMap` (`+0x00d0`) позволяет исследовать внутренние кольцевые буферы сообщений `HV_MESSAGE` между гостевыми ОС и сервисом `vmwp.exe` (Virtual Machine Worker Process).
