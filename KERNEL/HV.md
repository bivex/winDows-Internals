# Hyper-V HVL, VBS & SynIC Kernel Architecture Research (ARM64)

**Environment:**
- **OS:** Windows 11 Pro ARM64 (Build 26100.1)
- **Architecture:** ARM64 / AArch64 (EL1 Root Partition Kernel)
- **Debugger:** WinDbg Kernel Debugger via MCP Agent (`http://10.211.55.5:44445/mcp`)
- **Tooling:** `structscan v4.0` (Bayesian Multi-Feature Field Classifier & C/C++ Header Synthesizer)

---

## 1. Executive Summary

Гипервизор Microsoft Hyper-V является микроядерным гипервизором 1-го типа (Type-1 Bare-Metal Hypervisor), работающим на уровне привилегий **EL2** (на ARM64) / **VMX Root** (на x64). Операционная система Windows исполняется в **Root Partition** (EL1), взаимодействуя с гипервизором через **Hypervisor Interface Layer (HVL)** в `ntoskrnl.exe`.

Подсистема **Virtualization-Based Security (VBS)** добавляет третий уровень: **Secure Kernel** (`securekernel.exe`) исполняется в **VTL 1** (Virtual Trust Level 1), изолированном гипервизором от обычного ядра VTL 0 через SMC-вызовы (`HVC #N`).

## 3. VTL0 → VTL1 Переход: HVC #2 (ARM64 Secure Monitor Call)

На ARM64 переход между **VTL 0** (обычное ядро) и **VTL 1** (Secure Kernel) осуществляется через инструкцию `HVC #2`:

### 🔬 Дизассемблирование `nt!HvlpCallVtl1` (Live на ARM64 Build 26100.1)

```asm
nt!HvlpCallVtl1:
fffff802`ac02bc90  hvc  #2                   ; <- ARM64 HVC: VTL0 → VTL1 переход!
fffff802`ac02bc94  mov  fp, sp
fffff802`ac02bc98  lsr  w1, w19, #8
fffff802`ac02bc9c  and  w1, w1, #0x7f
fffff802`ac02bca0  cmp  w1, #7               ; Проверка кода возврата VTL
fffff802`ac02bca4  bne  nt!HvlpCallVtl1+0x3c
fffff802`ac02bcbc  lsr  x0, x19, #0x20      ; Извлечение статуса переключения
```

### 🔬 Дизассемблирование `nt!HvlSwitchToVsmVtl1` (Save ARM64 Callee Registers)

```asm
nt!HvlSwitchToVsmVtl1:
fffff802`ac02bc40  stp  fp, lr, [sp, #-0xB0]!  ; Сохранение всех callee-saved регистров
fffff802`ac02bc44  stp  x19, x20, [sp, #0x10]
fffff802`ac02bc48  stp  x21, x22, [sp, #0x20]
fffff802`ac02bc4c  stp  x23, x24, [sp, #0x30]
fffff802`ac02bc50  stp  x25, x26, [sp, #0x40]
fffff802`ac02bc54  stp  x27, x28, [sp, #0x50]
fffff802`ac02bc58  stp  d8, d9,   [sp, #0x60]  ; Сохранение NEON/FP регистров
fffff802`ac02bc5c  stp  d10, d11, [sp, #0x70]
fffff802`ac02bc60  stp  d12, d13, [sp, #0x80]
fffff802`ac02bc64  stp  d14, d15, [sp, #0x90]
fffff802`ac02bc70  ldr  x19, [x1], #8
fffff802`ac02bc74  ldr  x4, [x1]
fffff802`ac02bc7c  ldp  q8, q9, [x1], #0x20   ; Загрузка VTL1 контекста (SIMD)
```

**Вывод:** `HvlSwitchToVsmVtl1` сохраняет **весь ARM64 callee-saved контекст** (x19–x28, d8–d15) перед вызовом `HvlpCallVtl1 → HVC #2`. Это полноценная смена CPU-контекста, аналог `setjmp` уровня гипервизора.

## 4. SynIC (Synthetic Interrupt Controller) — Механика SINT

Synthetic Interrupt Controller (SynIC) — компонент Hyper-V, реализующий программные прерывания для межпартиционной сигнализации (VMBus channels, HV_MESSAGE).

### 🔬 Дизассемблирование `nt!HvlGetVpSintMessagePage`

```asm
nt!HvlGetVpSintMessagePage:
fffff802`abed1bc0  pacibsp                          ; ARM64 PAC защита стека
fffff802`abed1bc4  stp  fp, lr, [sp, #-0x10]!
fffff802`abed1bcc  bl   nt!HvlGetLpIndexFromProcessorIndex  ; LP Index из CPU#
fffff802`abed1bd0  bl   nt!HvlpGetLpcbByLpIndex            ; LPCB (Logical Processor Control Block)
fffff802`abed1bd4  ldr  x0, [x0, #0x20]                    ; SINT Message Page @ LPCB+0x20
fffff802`abed1bd8  ldp  fp, lr, [sp], #0x10
fffff802`abed1bdc  autibsp
fffff802`abed1be0  ret
```

**Вывод:** `HvlGetVpSintMessagePage` читает указатель на **SINT Message Page** из `LPCB+0x20` (Logical Processor Control Block, смещение 0x20). Эта страница хранит входящие `HV_MESSAGE` структуры с данными от гипервизора.

### 🔬 Дизассемблирование `nt!HvlpSintInterruptRoutine` (SynIC ISR)

```asm
nt!HvlpSintInterruptRoutine:
fffff802`abc3dcb0  pacibsp
fffff802`abc3dcc0  ldr  w8, [x0, #0x58]            ; Чтение SINT index из IRQ объекта
fffff802`abc3dcc4  sub  w19, w8, #0x300             ; Нормализация SINT номера (offset 0x300)
fffff802`abc3dcc8  adrp x8, nt!PpmPolicyConfigTable+0x140
fffff802`abc3dccc  ldr  w8, [x8, #0xA90]
fffff802`abc3dcd0  tbz  w8, #1, ...                 ; Проверка feature flag SynIC
fffff802`abc3dce8  blr  x15                         ; Indirect call → зарегистрированный SINT callback
```

## 5. VMBus (`nt!SbiVmbusArrivalEvent`)

VMBus — виртуальная шина межпартиционного обмена. В ядре NT: `SbiVmbusArrivalEvent` (`0xfffff802ac7637c0`).

```cpp
// Auto-generated by StructScan v4.0 | Target: nt!SbiVmbusArrivalEvent

typedef struct _RECONSTRUCTED_nt_SbiVmbusArrivalEvent {
    /* +0x0000 */ uint8_t  Padding_0000[64];           // Заголовок Event-объекта
    /* +0x0040 */ uint64_t EventControlFlags;           // 0x4000000000d
    /* +0x0048 */ PVOID    EventWaitBlock;
    /* +0x0058 */ uint64_t SintVector;                  // 0x12 (SINT #18 = VMBus)
    /* +0x0068 */ uint64_t SessionId;                   // 0x1dd224a80ac4d81
    /* +0x0070 */ uint64_t AsidMask;                    // 0xffff (65535)
    /* +0x0078 */ PVOID    KciAsidBitmapBuffer;         // nt!KciAsidBitmapBuffer
    /* +0x0080 */ uint64_t AsidBitmapSize;              // 0x3b80 (15232 bytes)
} RECONSTRUCTED_nt_SbiVmbusArrivalEvent;
```

**Ключевые поля:**
- `SintVector = 0x12` → VMBus использует **SINT #18** для сигнализации о прибытии новых пакетов.
- `KciAsidBitmapBuffer` — указатель на битмаску ASID-изоляции ядра (**Kernel Code Integrity**) для MMU-уровневого разграничения памяти VMBus-каналов.

## 6. VTL Call Descriptor (`nt!HvlpVsmVtlCallVa`)

Переменная `nt!HvlpVsmVtlCallVa` (`0xfffff802aca01898`) хранит виртуальный адрес страницы VTL Call Descriptor, через которую ядро VTL 0 передаёт вызов в Secure Kernel VTL 1. На момент исследования значение = `NULL` (гипервизор не в режиме VSM).

## 7. SMC Таблица VBS (`nt!VslpSmcTable`)

```cpp
// Auto-generated by StructScan v4.0 | Target: nt!VslpSmcTable (0xfffff802ac7637e0)

typedef struct _RECONSTRUCTED_nt_VslpSmcTable {
    /* +0x0020 */ uint64_t SmcControlFlags;    // 0x4000000000d (popcount=4)
    /* +0x0028 */ PVOID    SmcDispatchTable;
    /* +0x0038 */ uint64_t SmcDispatchVector;  // 0x12 (Vector 18)
    /* +0x0048 */ uint64_t SmcCookie;          // 0x1dd224a80ac4d81
    /* +0x0050 */ uint64_t AsidMask;           // 0xffff (65535 ASID)
    /* +0x0058 */ PVOID    KciAsidBitmapBuffer; // nt!KciAsidBitmapBuffer (KCI MMU isolation)
    /* +0x0060 */ uint64_t AsidBitmapSize;     // 0x3b80 (15232 bytes)
    /* +0x0080 */ uint64_t Vtl0AccessPerms;    // 0x3 (RW)
    /* +0x0088 */ uint64_t Vtl1Protected;      // 0x1 (VTL 1 Protected)
} RECONSTRUCTED_nt_VslpSmcTable;
```

- **`KciAsidBitmapBuffer` (`+0x0058`):** Буфер битмаски Address Space Identifier (ASID) для быстрой смены контекста MMU между VTL 0 и VTL 1 без дорогостоящего сброса TLB.

## 9. Механика Гиперколлов (ARM64 vs x64)

| Вызов | ARM64 | x64 |
|---|---|---|
| Гиперколл к EL2 (HV) | `HVC #0` | `VMCALL` / `VMMCALL` |
| Переход VTL0 → VTL1 | `HVC #2` | `VMCALL` с VTL код |
| Secure Monitor | `SMC #0` | N/A |

### Гиперколлы HvCallXxx:
- `HvCallPostMessage` — отправка `HV_MESSAGE` в другую партицию
- `HvCallSignalEvent` — сигнал через SynIC SINT
- `HvCallCreateVirtualProcessor` — создание vCPU
- `HvCallModifyVtlProtectionMask` — изменение защиты памяти VTL

## 10. Безопасность и Forensics

### DKOM / Hyper-V Escape Detection:
- **Изоляция Credential Guard:** Прямой доступ `LSASS` памяти из VTL 0 вызывает немедленный `SLAT Violation` на уровне EL2.
- **VMBus Ring Buffer Inspection:** Анализ SINT #18 и `AlpcMetaProviderMap` позволяет перехватывать `HV_MESSAGE` между гостевыми ОС и `vmwp.exe`.
- **VTL1 Attestation:** `VslQueryRuntimeAttestationReport` (`0xfffff802ac451348`) — точка получения TPM Attestation Report для проверки целостности Secure Kernel.
- **KCI ASID Bitmap Manipulation:** Потенциальный вектор атаки — модификация `KciAsidBitmapBuffer` с целью обхода MMU-изоляции VTL 1 (требует kernel write primitive).
